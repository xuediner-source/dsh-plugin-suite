# DSH upstream feature audit

This audit compares the six source repos recorded in [source-provenance.json](source-provenance.json) with DeepSeek Harness `0.2.0-rc.2` at [`639ed015`](https://github.com/deepseek-ai/deepseek-harness/commit/639ed015397290b3745d163aafe02ffee4aa3f84). Source links below pin each plugin to its audited commit, preserved in this suite through `source/<package>` tags. Original repository URLs in the provenance record are historical; the six source repositories were deleted at the owner’s request on 2026-10-02 after verified suite publication. “Partial” means DSH has a neighboring capability; it does not make the plugin redundant.

## Compatibility items for integration

- **Autocompact stream API — source defect and suite repair:** rc.2 sends terminal failures as `{ type: 'finish', reason: { kind: 'error', failure } }`, and normalizes adapter throws into that finish ([types](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm/src/types.ts#L152-L165), [runtime](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/llm/llm/src/index.ts#L1143-L1160)). Upstream looks for `chunk.kind === 'error'` and reads `.message` from a plain failure object incorrectly. The suite copy handles `finish.reason.failure`, and its peer range includes rc.2 ([suite code](../packages/dsh-autocompact/src/index.ts), [suite manifest](../packages/dsh-autocompact/package.json)).
- **Autocompact preset target — source finding and suite repair:** current presets are bundle declarations; the upstream skill documents `$DSH_HOME/.agent-presets` as a legacy format no longer read ([skill](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/preset/agent-preset/skills/editing-cordis-compositions/SKILL.md#L10-L12), [migration note](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/preset/agent-preset/skills/editing-cordis-compositions/SKILL.md#L66-L70)). The suite copy removes that injector and leaves native base-profile compaction in place ([suite code](../packages/dsh-autocompact/src/index.ts)).
- **Grok Memory lifecycle — source finding and suite repair:** rc.2 declares `agent/turn-stopping({ agent, turn, signal })` and `agent/disposed({ agent })`; source listens for undeclared `agent/settled`, and registers `compaction/*` log names as Cordis listeners even though DSH emits them as Session events ([turn events](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/agent/src/runtime-types.ts#L361-L381), [disposal](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/core/agent/src/runtime-types.ts#L258-L270), [compaction log events](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/compaction/compaction/src/types.ts#L17-L72)). The suite copy listens for supported inbox/session/disposal events and derives compaction invalidation from `session/event` ([suite runtime](../packages/dsh-grok-memory/lib/index.js#L545-L584)).
- **Provider route ownership:** native `llm-pi-ai` is dormant until routes are configured, then atomically claims those route IDs. `dsh-subs-hub` registers its configured provider IDs immediately; resolve duplicate IDs in configuration rather than loading both adapters for the same ID. The pinned source packages `dsh-xuediner-gateway` and `dsh-autocompact` declare `@deepseek-ai/dsh-llm: ^0.1.2-rc.1`, which excludes the audited `0.2.0-rc.2`; the suite copies update those peer ranges for packaging.
- **Gateway Settings API compatibility — source defect and suite repair:** the pinned plugin calls `ctx.get('settings').register()`/`.get()` and silently falls back when those methods are missing ([source `index.ts`](https://github.com/xuediner-source/dsh-plugin-suite/blob/3af4a4ff0ea26b0caacc36d14ce005211072d8ae/src/index.ts#L19-L68)). In DSH 0.2.0-rc.2, `@deepseek-ai/dsh-settings` projects active Loader `Config` schemas; it exposes `configure`, `describe`, and edits, not namespace registration/read methods ([settings service](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/settings/settings/src/index.ts#L222-L277), [form projection](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/settings/settings/src/index.ts#L302-L330)). The source row id is `xuediner-gateway`, while its LLM directory names `llm-xuedinerapi` and exports no `Config`, so native Model settings cannot resolve the provider form. The suite repairs this in [`src/index.ts`](../packages/dsh-xuediner-gateway/src/index.ts) and [`cordis.patch.yml`](../packages/dsh-xuediner-gateway/cordis.patch.yml): it exports volatile `baseURL` and credential-reference `apiKeyEnv` fields, resolves the selected key through `ctx.credentials` per WorkBuddy request, fails closed if a non-default reference is missing, uses the Loader entry id as `settingsNs`, and moves command/HTTP registration into optional child scopes. The real rc.2 [Loader + SettingsForms test](../packages/dsh-xuediner-gateway/test/settings-compat.test.mjs) edits an isolated profile, verifies the provider namespace and form schema, confirms the volatile edit applies without remounting, and verifies a missing custom credential does not fall through to another key. Published Cordis 4.0.4's `ctx.inject` and effect-scoped registration are compatible.
- **Gateway stream boundary — source finding vs suite repair:** upstream adapter code uses unbounded SSE accumulation, does not stop a pending body read after its header deadline, and can expose upstream diagnostic strings in errors. The suite adapter imports rc.2 `RequestMessage` and hardens all four SSE paths with bounded frames, cancellation of a blocked read, typed in-band quota/overflow failures, rejection of stream truncation without a terminal event, and credential/URL redaction in surfaced errors ([suite adapter](../packages/dsh-xuediner-gateway/src/adapter.ts), [stream regressions](../packages/dsh-xuediner-gateway/test/stream.test.mjs)). The source commit remains unchanged. CodeArts refresh-warning logs use the same safe error projection.
- **Gateway pool HTTP boundary — source finding vs suite repair:** the audited source registers exact pool paths on `ctx.webServer`, but its handlers check methods only on a subset of routes, accept unbounded CodeArts refresh bodies, turn malformed refresh JSON into “refresh all,” and have no loopback socket / Host / Origin fence ([source `pool-hub.ts`](https://github.com/xuediner-source/dsh-plugin-suite/blob/3af4a4ff0ea26b0caacc36d14ce005211072d8ae/src/pool-hub.ts#L908-L1188)). Its login-poll GETs can complete credential persistence, so their browser path must reject cross-site fetches. The suite candidate repairs all ten routes in [`http-guard.ts`](../packages/dsh-xuediner-gateway/src/http-guard.ts) and [`pool-hub.ts`](../packages/dsh-xuediner-gateway/src/pool-hub.ts): real socket loopback, bound-port loopback Host, exact same-Origin on POST and any supplied GET Origin, `Sec-Fetch-Site: cross-site` refusal, method/Allow validation, an 8 KiB JSON body ceiling, and 400 for malformed refresh input. Truly empty POSTs remain the `{}` shorthand; non-empty POST bodies require `application/json`. Errors project stable messages instead of upstream URLs or response/exception text. The source commit remains unchanged. The suite-only [loopback HTTP test](../packages/dsh-xuediner-gateway/test/pool-hub-http.test.mjs) uses a real local socket and fake upstream. It passed alongside the settings test and package typecheck/build; the full route/contract/no-secrets commands are recorded in the Gateway validation below. These endpoints remain an addon; DSH supplies `ctx.webServer.register`, but no native equivalent for this account-pool dashboard and its OAuth/task operations.

The upstream references remain read-only; suite code is a separate integration candidate. No live provider, OAuth, or paid API request was made. Gateway local verification from `suite/packages/dsh-xuediner-gateway` includes `npm run typecheck`, `npm run build`, `node test/settings-compat.test.mjs`, `node test/pool-hub-http.test.mjs`, `node test/contracts.mjs`, and `node test/no-secrets.mjs .`. The latest focused settings test also covers fail-closed resolution for a missing non-default credential reference.
